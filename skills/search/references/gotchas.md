# Ловушки — Exa, Firecrawl, снятие прайсов

Проверенные на прогонах отказы движков и биллинга. Формат: якорь + что делать.

**Дневной кап Exa гейтит только скрипт, не MCP.** `check_cap()` в `scripts/websearch.py` видит собственные `contents`/`search`/`both`, а вызовы `mcp__exa__web_search_exa` / `web_search_advanced_exa` из workflow-агентов идут мимо капа и мимо лога; `contents` в workflow зовётся с `--no-log` ($0,001/стр.). `spent_today()` считает по локальной дате — в полночь обнуляется. Пре-флайт «Exa < $0,60» трактовать как ориентир, не как блокер (26.08.2026: $0,71 за день, волна прошла без отказов); реальный расход — поле `spend.exaUsd` в результате workflow или кабинет Exa.

**`firecrawl_crawl` затягивает PDF/ODT/EPUB-выгрузки и биллит их постранично.** 01.09.2026 на мануалах omimo.org crawl подтянул PDF/ODT/EPUB/ZIM рядом с HTML — **472 кредита вместо ~76**; хук `block-pdf-firecrawl.py` ловит только scrape/extract с явным PDF-URL, crawl он не видит. В любом `firecrawl_crawl` задавать `excludePaths: [".*\\.(pdf|odt|ods|epub|zim|docx?|xlsx?|dot|xltx)$"]` (или `includePaths` только на HTML-маршруты) и вписывать это требование субагенту в промпт явно — запрета «не скрейпить PDF» ему недостаточно.

**`formats:["json"]` на маркетплейсах и прайсах с калькулятором выдумывает данные.** Fiverr/Upwork при statusCode 200 вернули несуществующие «21,000+ results» и гиги из чужой категории; у ScaledMail — «$50/mailbox, minimum 25» вместо «$50/домен при 25 ящиках», у Instantly Inbox Placement — выдуманные тиры целиком. Брать `formats:["markdown"]` и парсить самому; json — только для простых статичных страниц и всегда со сверкой по markdown. Оба маркетплейса отдаются с `proxy:"stealth"`, `waitFor 4000–5000`, `maxAge:0`; ~5 кредитов/страница (json — 9). Многословный AND-запрос в Upwork даёт честный 0, а не капчу.

**Прайс SaaS — сначала `<домен>/pricing.md`, потом Firecrawl.** Вендоры кладут машиночитаемый прайс для агентов (проверено на `instantly.ai/pricing.md` и `smartlead.ai/pricing.md`): полные таблицы тарифов, аддонов и лимитов. Тянуть `curl -sL -A "Mozilla/5.0"` — 0 кредитов. Годовая цена за тумблером Monthly/Yearly снимается `actions: [{type:"executeJavascript", script:"…"}, {type:"wait"}]` кликом по листовым элементам с текстом `Yearly`; верхнеуровневый `return` в скрипте падает с `SyntaxError: Illegal return statement` — писать выражение без `return`.

**Brave 402 и 403 — два разных отказа биллинга, оба не про пустую выдачу.** `HTTP 402 USAGE_LIMIT_EXCEEDED` (`current_spend: 30`, `usage_limit: 30`, monthly) — месячный кап $30, сбрасывается 1-го числа (впервые 23.08.2026 в `/daily-news-swot`). `HTTP 403 SUBSCRIPTION_TOKEN_DEACTIVATED` («The provided subscription token is deactivated») — аккаунт **suspended** из-за непрошедшей карты; после оплаты инвойса реактивация **ручная**: Brave просит ответить на письмо `searchapi-support@brave.com`. Дашборд `api-dashboard.search.brave.com` при этом отдаёт 403 (awselb) даже анонимно — не диагностический признак. Менять `BRAVE_API_KEY` бесполезно: ключ исправен. Что делать: 402/403 → не повторять и не считать тему проверенной; фоллбэк — Exa (`both` деградирует сам, exit 0), Рунет — `/yandex-search` (~0,03 ₽/запрос). Причину и дату suspension быстрее дашборда покажет `spark search --filter "from:brave newer_than:30d"`. Профильные субагенты с одним Brave (например `swot-news-enricher`) при любом из этих кодов молча отдают «новостей нет» — подменять их `general-purpose` с явной инструкцией про Exa/`/yandex-search`.
