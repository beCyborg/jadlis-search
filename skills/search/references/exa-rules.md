# Exa — правила формулировки и выбора параметров

Свёртка `exa-labs/agent-skills` (`build-with-exa`, `exa-search`, `exa-contents`) и `exa-mcp-server/skills/search/references/searching.md` (24.08.2026). Контракт API — `exa-api.md`.

## Как Exa ищет

Векторные эмбеддинги, не ключевые слова: «ты описываешь целевую страницу, Exa возвращает ближайших соседей в пространстве эмбеддингов». Булевы операторы (`AND`/`NOT`) — просто слова; кавычки не форсят точную фразу; 1–2-словные запросы дают разброс. Exa возвращает **похожесть, не валидацию** — результаты фильтровать глазами.

## Десять правил

1. **Дефолтный запрос** = `query` + `type:"auto"` + `contents:{highlights:true}` и больше ничего. Каждое доп. поле — только если задача его явно требует.
2. **Описывай страницу, а не факт.** «detailed blog post about X written by a practitioner», не «X». Натуральная грамматическая фраза (в старых доках — «как текст ссылки-анкора»).
   | Ищем | Плохо | Хорошо |
   |---|---|---|
   | Посты про X | `X` | `detailed blog post about X written by a practitioner` |
   | Компанию, делающую Y | `Y company` | `category:company startup building Y for enterprise` |
   | Человека в компании | `person at company` | `category:people senior engineer at Acme` |
3. **Highlights, не text**, для агентных циклов (×10 меньше токенов, без задержки). `text` — когда нужен контекст всей страницы (кап `maxCharacters`). `summary` — только по явной просьбе (LLM-вызов на каждый результат, +$0.001/стр.). Не стекать все три — биллинг умножается.
4. **`auto` почти всегда прав.** `fast`/`instant` — только латентно-критичные пути; `deep`/`deep-reasoning` — когда сам поиск требует многошагового рассуждения, а не «хочу структурный вывод» (`outputSchema` работает на любом типе).
5. **`numResults` не задавать** (default 10). Если задавать: 5 — именованная сущность, 10 — точный фильтр, 15 — широкая разведка. **Никогда >25**: лучше 2–3 запроса с разных углов по 10–15, чем один на 50.
6. **Не выдумывать фильтры.** `category`/`includeDomains`/`excludeDomains` — только когда пользователь явно просит и даёт список; иначе — предпочтения источников в формулировке. Невалидные категории (`github`, `documentation`, `qa`, `pdf`) → 400. `company`/`people` отключают `startPublishedDate`/`endPublishedDate`/`excludeDomains`.
7. **`maxAgeHours` = свежесть краула, не публикации.** По умолчанию не слать. Свежесть публикации — `startPublishedDate`/`endPublishedDate` или семантика в запросе («published in March 2026»); даты считать от текущей, не из примеров.
8. **Форма тела:** в `/search` `text/highlights/summary` внутри `contents`; в `/contents` — верхнего уровня. `tokensNum` — только `/context`.
9. **`systemPrompt` = поведение, `outputSchema` = форма** (глубина ≤2, ≤10 свойств, без полей citations/confidence — grounding приходит сам).
10. **Проверять `statuses` у `/contents`** — HTTP 200 не значит, что все URL успешны.

## Разнообразие запросов

- «overhyped» vs «overrated» vs «disappointment» — один угол. Скептик vs строитель vs практик — разные углы.
- Порядок слов меняет эмбеддинг — при важном запросе 2–3 формулировки параллельно.
- Пусто → (a) длиннее и конкретнее, (b) другой угол, не синоним, (c) несколько углов пусто = темы в вебе мало, так и сообщать.

## Категории

| `category` | Для чего | Ограничения |
|---|---|---|
| `company` | страницы компаний, LinkedIn-профили компаний | нет `start/endPublishedDate`, `excludeDomains` |
| `people` | данные о людях из многих источников, LinkedIn | то же; `includeDomains` — только LinkedIn |
| `publication` | научные публикации с метаданными (авторы, venue, цитирования) | — |
| `news` | текущие события, журналистика | — |
| `personal site` | блоги, личные страницы — «уникальная сила Exa» | — |
| `financial report` | SEC-филинги, отчёты | — |

## Русский язык (живая матрица 24.08.2026)

- `auto`/`fast` на RU-запрос уходят в **англоязычные** источники (кросс-язычная семантика): для науки/медицины это плюс, для Рунета — мимо.
- Русские страницы даёт `--type keyword` (лексический), `neural` — русские, но шумнее. Глубокий Рунет/регионы/операторы — `/yandex-search`.
- Формулировать на языке ожидаемых результатов; для RU-семантики — полное предложение, не 2 слова.

## Brave vs Exa — формулировка

| | Brave | Exa |
|---|---|---|
| Модель | keyword-индекс | эмбеддинги |
| Запрос | ключевые слова: `React server components architecture explained 2026` | описание страницы: `technical blog post explaining how React server components work internally` |
| Операторы | `site:`, кавычки, goggles работают | не работают; домены — `--include-domains` |
| Свежесть | `--freshness pd\|pw\|pm\|py` | `--start/--end` или семантика даты |
| Регион/язык | `--country`, `--lang` | `--country` (`userLocation`); язык — через формулировку/`keyword` |

`both` шлёт один и тот же текст обоим движкам; когда формулировки должны различаться — `--query-exa "<описание страницы>"`.

## Латентный рецепт

`{"type":"instant","contents":{"highlights":true,"maxAgeHours":-1}}` — ~250 мс, только кэш.
